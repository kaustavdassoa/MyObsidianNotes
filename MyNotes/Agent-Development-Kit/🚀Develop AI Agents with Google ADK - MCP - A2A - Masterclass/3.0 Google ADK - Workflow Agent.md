# Google ADK - Workflow Agents

**Reference:** https://google.github.io/adk-docs/agents/workflow-agents/

> [!info] What are Workflow Agents?
> **[[Workflow Agents]]** are specialized agents that control the execution flow of their sub-agents. They do not necessarily generate content themselves; instead, they act as orchestrators.

There are three main categories of workflow agents:
* **[[Sequential Agent]]**: Executes sub-agents one after another, in **sequence**.
* **[[Parallel Agent]]**: Executes multiple sub-agents in **parallel**.
* **[[Loop Agent]]**: **Repeatedly** executes its sub-agents until a specific termination condition is met.

## Why Use Workflow Agents?

Workflow agents are essential when you need explicit control over how a series of tasks or agents are executed. They provide:

* **Predictability:** The flow of execution is guaranteed based on the agent type and configuration.
* **Reliability:** Ensures tasks run in the required order or pattern consistently.
* **Structure:** Allows you to build complex processes by composing agents within clear control structures.

> [!note] Agent Composition
> While the workflow agent manages the control flow deterministically, the [[Sub-agents]] it orchestrates can themselves be any type of agent, including intelligent LLM Agent instances. This allows you to combine structured process control with flexible, LLM-powered task execution.

## Sequential Agents

> [!summary] How Sequential Agents Work
> A **[[Sequential Agent]]** acts as a linear pipeline. It triggers its sub-agents in the exact order they are listed in the `sub_agents` array. The output generated by one agent is typically appended to the conversational context or explicitly passed as input to the next agent in the sequence.

**When to Use:**
Use sequential agents for multi-step workflows where a subsequent step inherently relies on the completion and output of the previous step (e.g., *Drafting an email -> Reviewing the email -> Translating the email*).

**Best Practices:**
* Keep the scope of each sub-agent narrow and highly focused on a single task.
* Clearly define the output expectations of one agent so the next agent receives clean, predictable context.

> [!code] Sequential Agent Example
> Below is a conceptual example of a Sequential Agent that first researches a topic, then summarizes the research.

```python
from google.adk.agents import SequentialAgent, LlmAgent

# 1. First agent gathers information
researcher_agent = LlmAgent(
    name="researcher",
    model="gemini-2.5-flash",
    description="Researches a given topic and provides raw facts.",
    instruction="Gather 5 key facts about the given topic."
)

# 2. Second agent formats the output
summarizer_agent = LlmAgent(
    name="summarizer",
    model="gemini-2.5-flash",
    description="Takes raw facts and turns them into a short paragraph.",
    instruction="Write a cohesive paragraph using the provided facts."
)

# 3. The Sequential Agent orchestrates them
pipeline_agent = SequentialAgent(
    name="research_pipeline",
    description="Runs the researcher, then passes data to the summarizer.",
    sub_agents=[researcher_agent, summarizer_agent] # Executes in this exact order
)
```

## Parallel Agents

> [!summary] How Parallel Agents Work ?
>  A **[[Parallel Agent]]** executes all of its defined sub-agents simultaneously. This is highly efficient for tasks that are independent of one another. Once all sub-agents have finished their execution, the Root Agent (the Parallel Agent) collects their responses. Typically, the framework combines these responses into a single structured output (like a dictionary), where the results are mapped to the names of the respective sub-agents.

**Challenges:**
- **Rate Limiting:** Spawning too many sub-agents at once might trigger API quota limits.
- **Error Handling:** If one sub-agent fails, you must decide whether the entire parallel operation fails or if it should return partial results.
- **Context Size:** Combining massive outputs from multiple agents simultaneously could exceed the context window of subsequent downstream tasks.

**Best Practices:**
- Only use parallel execution for tasks that have zero dependencies on each other.
- Monitor your API limits carefully when deploying parallel branches.

## Loop Agents

> [!summary] How Loop Agents Work A **[[Loop Agent]]** iteratively cycles through its sub-agents. It is typically used for refinement, critique, or self-correction workflows.
> 
> **How it exits a loop:** A loop agent continues to run until a specific termination condition is met. This is usually achieved by either hitting a hardcoded `max_iterations` limit (a crucial safety mechanism) or by a sub-agent invoking a specific tool that changes the execution state (e.g., setting `escalate = True` on the tool context).

**Best Practices:**

- **Always set a `max_iterations`** attribute to prevent infinite, expensive LLM loops.
- Define explicitly clear exit conditions in the prompt of the evaluating agent so it knows exactly when to trigger the exit tool.

> [!info] Code Explanation 
> In the code block below, a `SequentialAgent` orchestrates the workflow.
> 
> 1. It first runs a `code_writer_agent` to draft an initial script.
> 
> 2. It then enters the `refinement_loop_agent`. Inside this loop, the `code_reviewer_agent` critiques the code.
>    
> 3. The `code_refiner_agent` takes the critique to fix the code. If the reviewer stated "No Issues Found", the refiner is instructed to call the `exit_loop` tool.
>    
> 4. The `exit_loop` tool sets `tool_context.actions.escalate = True`, which signals the loop to break, preventing further iterations.


```python 

from google.adk.agents import LoopAgent, LlmAgent, SequentialAgent
from google.adk.tools.tool_context import ToolContext

  

def exit_loop(tool_context: ToolContext):
  tool_context.actions.escalate = True
  return {}

  
#Basic Code generation agent 
code_writer_agent = LlmAgent(
    model="gemini-2.5-flash",
    name="code_writer_agent",
    description="Writes Python code based on a user condition.",
    instruction="""
    When given a condition, write the working python code. Make sure not to  add comments and you don't need to adhere to Python best practices
    """,
    output_key = 'python_program'  # Output key to store the raw code 
)

  
#Reviewer Agent
code_reviewer_agent = LlmAgent(
    model = 'gemini-2.5-flash',
    name="code_reviewer_agent",
    description="Reviews the provided Python code provides the review comment.",
    instruction="""
    Review the python code {{python_program}} and provide your review comment.
    Please make sure you are checking if proper comments are given and Python best practices are followed.
     When you think the code meets the required condition, respond exactly with the phrase "No Issues Found" 
     """,
    output_key = 'reviewed_comments',
)

code_refiner_agent = LlmAgent(
    model = 'gemini-2.5-flash',
    name="code_refiner_agent",
    include_contents='none',
    description="Refines the provided Python code based on review comment provided.",
    instruction=""" 
    Refine the provided Python code {{python_program}} based on review comments {{reviewed_comments}}.  
    If the review comment is *exactly* "No Issues Found" you MUST call the 'exit_loop' function. Do not output any text.
    Do not add explanations. Either output the refined program OR call the exit_loop function.
     """,
    tools=[exit_loop], #Tool call exit loop to stop the execution
    output_key = 'python_program'
)

# Loop Agent 
refinement_loop_agent = LoopAgent(
    name="refinement_loop_agent",
    sub_agents=[
        code_reviewer_agent,
        code_refiner_agent,
    ],
    max_iterations=5
)
 
# Craete Sequence Agent to run code writter and refine (loop) agent in sequence.  
root_agent = SequentialAgent(
    name="python_code_writter_agent",
    description="Writes an initial python program and then iteratively refines it with review comments and exits using an exit tool."
    sub_agents=[
        code_writer_agent,       # Run first to create initial doc
        refinement_loop_agent    # Then run the critique/refine loop
    ],

)
```
