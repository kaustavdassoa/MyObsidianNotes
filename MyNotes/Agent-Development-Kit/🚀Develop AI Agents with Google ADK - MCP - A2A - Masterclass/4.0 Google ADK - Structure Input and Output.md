# Google ADK - Structure Input and Output

#### Defining Input Output Structure

> [!info] Defining and Leveraging Agent Schemas
> The [[Input Schema]] and [[Output Schema]] of an [[Agent]] act as strict contracts that define exactly what information the agent requires to operate and what structure it guarantees to return. 
> 
> **How they are defined:**
> Typically, these structures are defined using data validation libraries like **[[Pydantic]]**. Developers create Python classes inheriting from `BaseModel`, specifying the exact fields, data types (e.g., strings, integers), and providing clear natural-language descriptions for each field using `Field(description="...")`.
> 
> **How they are leveraged by an agent:**
> * **Predictability:** By defining an [[Output Schema]], the agent is forced to respond in a predictable, machine-readable format (like a structured JSON object) instead of unstructured natural language. This is crucial for integrating the agent into larger software workflows.
> * **Validation:** The [[Input Schema]] ensures the agent automatically validates incoming requests, rejecting or prompting for correction if required parameters (like a specific ID or formatted string) are missing.
> * **Contextual Prompting:** Frameworks dynamically inject the schemas' field descriptions directly into the LLM's system prompt, acting as implicit instructions that guide the model on how to extract and map the data accurately.

---

> [!summary] Code Implementation Summary
> The code block below demonstrates how to strictly type an agent's input and output using Pydantic models. 
> * **Input Mapping:** The `CountryInput` class defines the expected user input as a single string field (`country`). This is mapped to the agent via the `input_schema` parameter.
> * **Output Mapping:** The `CapitalOutput` class dictates that the agent must return a specific JSON structure containing a `capital` string. This is mapped via `output_schema`.
> * **Instruction Enforcement:** The agent's `instruction` parameter explicitly references the `CapitalOutput` schema (`json.dumps(CapitalOutput.model_json_schema())`), heavily reinforcing the LLM's behavior to exclusively output the requested structured JSON data instead of conversational text.

```python 
#Pydantic Class to define the input schema
class CountryInput(BaseModel):
    country: str = Field(description="The country to get information about.")

#Pydantic Class to define the output schema
class CapitalOutput(BaseModel):
    capital: str = Field(description="The capital city of the country.")

# Agent Definition 

root_agent = LlmAgent(
    name="capital_agent",
    model="gemini-2.5-flash",
    description="An agent that helps with capital of a country",
    instruction=f"""
    You are an agent which returns the capital of a country when the country name is provided in json format {{"country": "Canada"}}. If the format is not maintained by user, suggest to use the json format. Respond ONLY with a JSON object matching this exact schema: {json.dumps(CapitalOutput.model_json_schema(), indent=2)}
    """,
    input_schema=CountryInput,   #Input Format 
    output_schema=CapitalOutput, #Output Format 
)
