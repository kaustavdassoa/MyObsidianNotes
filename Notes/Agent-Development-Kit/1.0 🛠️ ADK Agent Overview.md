## 1. Technical Architecture & Component Logic

### 🏗️ System Blueprint

The ADK defines an agent through a specific functional equation rather than just a chatbot wrapper:

> [!IMPORTANT]
> 
> **Model** (Brain) + **Tools** (Actuators/Sensors) + **Orchestration** (Framework) = **Agent**

- **Model:** The reasoning engine (e.g., Gemini).
- **Tools:** Modular code for perception (Sensors) and action (Actuators).
- **Orchestration:** Automated by the `Agent` class; manages the **Perceive → Think → Act → Check** loop.

### 🧠 State & Memory Management

Context is handled via **Session State** (Python dictionary). Use prefixes to control data persistence:

|**Prefix**|**Scope**|**Lifecycle**|**Use Case**|
|---|---|---|---|
|`temp:`|**Invocation**|Discarded after one turn|Intermediate calculations|
|_(none)_|**Session**|Persists for current chat|Conversation history|
|`user:`|**User**|Tied to `user_id` across sessions|User preferences/Language|
|`app:`|**Global**|Shared across all users/sessions|API endpoints/Feature flags|

> [!TIP]
> 
> **Dynamic Injection:** Inject state into instructions using: `Help the user in {user:language?English}.`

## 2. Code Implementation & Syntax

### 📦 Initialization Patterns

You can define agents via Python code or YAML manifests.

```python
from google.adk.agents.llm_agent import Agent

root_agent = Agent(
    model='gemini-2.5-flash',
    name='root_agent',
    instruction='You are a helpful assistant.'
)
```

**YAML (`agent_config.yaml`):**



```yaml
name: assistant_agent
model: gemini-2.5-flash
instruction: |
  You are a patient algebra tutor.
  1. Understand the struggle.
  2. Break down the problem.
```

### 🔧 Custom Tool (Actuator) Definition

Tools require strict type hints and docstrings for the LLM to understand them.


```python
def calculate_shipping_cost(weight_kg: float, country: str) -> dict:
    """Calculates shipping cost.
    Args:
        weight_kg: Package weight in kg.
        country: Destination country.
    Returns:
        dict: {'status': 'success', 'cost_usd': 25.50}
    """
    return {"status": "success", "cost_usd": 25.50}

# Registering the tool
agent = LlmAgent(tools=[calculate_shipping_cost])
```

## 3. Best Practices & Design Patterns

### 🎖️ The "Golden Rules"

1. **5-Pattern Instructions:** Structure instructions with: **Identity, Mission, Methodology, Boundaries, and Few-shot examples.**
2. **Strategic Tool Guidance:** Don't just list tools; tell the agent _when_ and in what _sequence_ to use them.
3. **Structured Output:** Always use **Pydantic BaseModels** via the `output_schema` parameter for predictable JSON.
    

### 🚀 Scalability & Deployment

- **Model Strategy:** Prototype on `gemini-2.5-pro` $\rightarrow$ Production on `gemini-2.5-flash` (10x cheaper).
- **Agent-as-Tool:** Use `AgentTool` to let a "Manager" agent delegate to "Specialist" agents.
- **Headless Deployment:** Use `adk api_server` to run the agent as a REST API.

## 4. Error Handling & Debugging

> [!CAUTION] Common Pitfalls
> 
> - **Tool Mixing:** ADK supports only **one** built-in tool (like Google Search) per agent.
>     
> - **Missing Hints:** Always provide type hints; avoid default values in tool parameters.
>     
> - **Crashes:** Use `{var?default}` instead of `{var}` to prevent crashes if a state key is missing.
>     

### 🔍 Observability

To see "Thought Traces," use the `BuiltInPlanner`:

```Python
planner=types.ThinkingConfig(include_thoughts=True)
```

## 5. Production Implementation Roadmap

1. **Environment:** `adk create my_agent` + setup `.env` for secrets.
2. **Persona:** Craft 5-Pattern instructions on `gemini-2.5-pro`.
3. **Capabilities:** Attach `McpToolset` or custom Python functions.
4. **Context:** Map persistence using `temp:`, `user:`, or `app:` namespaces.
5. **Hardening:** Switch to `flash`, set `BLOCK_LOW_AND_ABOVE` safety, and launch `api_server`.
