### 1. Built-in Tools
Built-in tools are imported directly from the framework. The most critical aspect here is ensuring you pass the tool instance directly into the `tools` array.

```Python
from google.adk.agents import LlmAgent
from google.adk.tools import google_search, code_interpreter

# Standard Initialization
research_agent = LlmAgent(
    model="gemini-2.5-flash",
    name="regulatory_researcher",
    description="Finds the most up-to-date SEC or RBI regulatory publications.",
    instruction="""
    Use google_search to find current regulatory information. 
    Always cite your sources and explain recency.
    """,
    # NOTE: While you can import multiple, best practice dictates routing 
    # to separate specialized agents if combining search and code execution 
    # causes context confusion.
    tools=[google_search] 
)
```

### 2. Custom Function Tools
This is where you integrate proprietary logic. The ADK uses the `ToolContext` object to allow your function to read/write to the agent's memory state mid-execution.

```python
from google.adk.tools.tool_context import ToolContext
from typing import Optional
import logging

logger = logging.getLogger(__name__)

# The docstring and type hints are natively parsed by the ADK into a JSON schema
def validate_kyc_status(account_id: str, region: str, tool_context: ToolContext, force_refresh: Optional[bool] = False) -> dict:
    """
    Checks the KYC/AML compliance status for a given banking customer.
    
    Args:
        account_id (str): The unique 10-digit identifier for the customer account.
        region (str): The regulatory region (e.g., 'APAC', 'EMEA', 'NAM').
        tool_context (ToolContext): Automatically injected by ADK for state manipulation.
        force_refresh (bool, optional): If True, bypasses cache. Defaults to False.
        
    Returns:
        dict: The compliance status, risk score, and system flags.
    """
    try:
        # 1. Accessing session state via tool_context
        # Use prefixes like 'user:' or 'app:' for broader scope
        active_auditor = tool_context.state.get("user:auditor_id", "system_automated")
        
        # [Insert proprietary database lookup logic here]
        
        # 2. Advanced Control: Modifying framework behavior
        # Set to True if you want the ADK to return this raw JSON directly to the user,
        # bypassing the LLM's final summarization step.
        tool_context.skip_summarization = False 
        
        return {
            "status": "success", 
            "account": account_id, 
            "compliance_status": "CLEARED",
            "risk_score": 12.5,
            "audited_by": active_auditor
        }
    except Exception as e:
        logger.error(f"KYC Validation failed: {str(e)}", exc_info=True)
        # Always return a structured error dictionary so the LLM can recover gracefully
        return {"status": "error", "error_message": f"Validation failed: {str(e)}"}
```

### 3. Model Context Protocol (MCP) Tools

The `McpToolset` handles the connection lifecycle to external servers via standard I/O streams or HTTP. This example demonstrates a critical security best practice: the `tool_filter`.

Python

```python
from google.adk.agents import LlmAgent
from google.adk.tools.mcp_tool import McpToolset
from google.adk.tools.mcp_tool.mcp_session_manager import StdioConnectionParams
from mcp import StdioServerParameters
import os

# Define the connection to a local or remote MCP server (e.g., a PostgreSQL DB)
db_mcp_tool = McpToolset(
    connection_params=StdioConnectionParams(
        server_params=StdioServerParameters(
            command="npx",
            args=[
                "-y",
                "@modelcontextprotocol/server-postgres",
                os.environ.get("DATABASE_URL")
            ],
            # Optional: Inject specific environment variables required by the MCP server
            env={"CUSTOM_TIMEOUT": "3000"} 
        )
    ),
    # SECURITY BEST PRACTICE: Explicitly define which tools the agent can use.
    # For a banking database, strictly omit write/drop capabilities.
    tool_filter=['read_query', 'list_tables', 'describe_schema'] 
)

database_agent = LlmAgent(
    model='gemini-2.5-flash',
    name='db_query_assistant',
    instruction='Help the user query the compliance database safely.',
    tools=[db_mcp_tool]
)
```

### 4. Agent-as-a-Tool (Specialized Delegation)

This wraps a fully independent `LlmAgent` inside the `AgentTool` class, allowing the parent Orchestrator to trigger it exactly like a Python function. Notice the use of `output_key` to isolate the sub-agent's findings in the memory state.

Python

```python 
from google.adk.agents import LlmAgent
from google.adk.tools.agent_tool import AgentTool

# 1. Define the Sub-Agent (The Specialist)
aml_auditor_agent = LlmAgent(
    model="gemini-2.5-pro", # Use the heavier model for complex reasoning
    name="aml_specialist",
    description="Analyzes transaction logs for Anti-Money Laundering (AML) risks.",
    instruction="Review the provided transaction history and flag anomalies.",
    # CRITICAL: Isolate the output of this agent into a specific state key
    # to prevent it from overwriting the parent agent's context.
    output_key="aml_audit_report" 
)

# 2. Wrap the Sub-Agent
aml_tool = AgentTool(
    agent=aml_auditor_agent,
    # If True, the parent Orchestrator will not paraphrase the sub-agent's output.
    # Useful when the sub-agent generates strict JSON or legal text that shouldn't be altered.
    skip_summarization=False 
)

# 3. Equip the Main Orchestrator
orchestrator_agent = LlmAgent(
    model="gemini-2.5-flash", # Use the faster, cheaper model for routing
    name="regops_orchestrator",
    instruction="""
    You are the RegOps Orchestrator. 
    When asked to review an account, first delegate the AML checks to the aml_specialist.
    Wait for its report, then synthesize a final summary for the user.
    """,
    tools=[aml_tool] # The orchestrator treats the sub-agent as a tool capability
)
```
