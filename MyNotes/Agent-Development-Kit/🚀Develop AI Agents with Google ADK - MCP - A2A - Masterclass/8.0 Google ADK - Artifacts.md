# Google ADK - Artifacts

> [!info] What are Artifacts?
> In the context of [[Google ADK]], **[[Artifacts]]** represent a crucial mechanism for managing named, versioned binary data. While standard state or memory handles text and simple key-value pairs, artifacts allow agents and tools to process, store, and share non-textual data—such as images, PDFs, audio files, and spreadsheets. 
> 
> * **Structure:** An artifact is represented using the standard `types.Part` object, specifically utilizing the `inline_data` field to store the raw binary bytes and its associated `mime_type` (e.g., `"image/png"`).
> * **Scope:** They are identified by a unique filename and can be scoped either to a specific conversation [[Session]] or globally to a [[User]] across multiple sessions.

---

## Why Use Artifacts?

While standard session state is great for small conversational context (strings, booleans, small dictionaries), it is not optimized for heavy files. You should use [[Artifacts]] for:

* **Handling Non-Textual Data:** Storing and retrieving images, audio clips, video snippets, or PDF documents.
* **Persisting Large Data:** Keeping large data blobs out of the standard session state to prevent clutter and memory bloat.
* **User File Management:** Allowing users to upload files for the agent to analyze, or allowing the agent to generate and provide downloadable files (like a CSV export).
* **Caching:** Storing the results of computationally expensive binary generations (like rendering a complex chart) so they don't need to be regenerated on every request.

---

## Core Concepts & Operations

The management of artifacts is handled by an implementation of the **[[BaseArtifactService]]**. This service acts as the central storage engine and defines how and where files are saved. Agents and tools interact with it via the following core operations:

> [!summary] Core Artifact Methods
> * **`save_artifact`**: Stores the artifact's binary data under a specified filename and automatically assigns it a new version number. 
> * **`load_artifact`**: Retrieves a specific version of an artifact (or the latest version if no specific number is provided) using its filename.
> * **`list_artifacts`**: Lists all the unique artifact filenames stored within a given scope (session or user).
> * **`Delete Artifact`**: Removes an artifact and potentially all of its versions. *(Note: For safety, deletion is typically handled directly via the service instance rather than through agent context objects).*

---

## Storage Options

Google ADK provides different implementations of the `BaseArtifactService` depending on whether you need temporary scaffolding or production-grade persistence.

### 1. In-Memory Artifact Service
* **Implementation:** `InMemoryArtifactService`
* **Characteristics:** Stores all binary data directly in the application's RAM.
* **Use Case:** Ideal for local prototyping, testing, and handling temporary files during a single runtime.

> [!warning] Volatile Storage
> Data stored via the [[In-Memory Artifact Service]] is **temporary**. It is completely lost when the agent restarts, the server crashes, or the application process ends.

### 2. Persistent Storage (Google Cloud Storage)
* **Implementation:** `GcsArtifactService`
* **Characteristics:** Leverages Google Cloud Storage (GCS) buckets to store each version of an artifact as a distinct cloud object (blob). 
* **Use Case:** Built for production environments requiring durable, scalable, and secure file management across distributed systems.

> [!note] Durable Storage
> Artifacts stored via the [[GcsArtifactService]] are **persistent**. They survive application restarts, can be shared across multiple server instances or agent microservices, and remain intact until explicitly deleted.


# Google ADK - Implementing Artifacts with a Summarizer Agent

> [!info] Practical Implementation of Artifacts
> To truly understand how [[Artifacts]] work in Google ADK, it helps to see them in action. Below is a complete implementation of a **Summarizer Agent**. 
> 
> This agent listens to user text, summarizes it, and actively uses custom tools to interact with the underlying `BaseArtifactService` to save the summary as a text file, list available files, and read them back.

## Use Cases Demonstrated
1. **`save_artifact`**: The agent converts its summarized text string into a binary byte array, formats it as a `types.Part` object with the correct `mime_type`, and saves it.
2. **`list_artifacts`**: The agent queries the storage scope to see what filenames currently exist.
3. **`load_artifact`**: The agent retrieves the binary data of a specific file and decodes it back into readable text.
4. **`delete_artifact`**: Demonstrated outside the agent's toolset. (As a best practice, deletion is usually handled administratively directly on the `artifact_service` instance rather than giving the LLM unrestricted delete access).

---

## Summarizer Agent Code Implementation

> [!code] Python Implementation
> This code uses the [[InMemoryArtifactService]] to demonstrate the workflow. For production, simply swap it with `GcsArtifactService`.

```python
import asyncio
from google.adk.agents import LlmAgent
from google.adk.runners import Runner
from google.adk.artifacts import InMemoryArtifactService
from google.adk.sessions import InMemorySessionService
from google.adk.tools import ToolContext
from google.genai import types

# ==========================================
# 1. Define Artifact Interaction Tools
# ==========================================

def save_summary_tool(context: ToolContext, filename: str, text_to_save: str) -> str:
    """Saves the summarized text into an artifact file."""
    # Convert string to binary bytes and wrap in a types.Part
    file_bytes = text_to_save.encode('utf-8')
    artifact_part = types.Part.from_bytes(data=file_bytes, mime_type="text/plain")
    
    # Save using the agent's execution context
    version = context.save_artifact(filename, artifact_part)
    return f"Successfully saved '{filename}' as version {version}."

def load_summary_tool(context: ToolContext, filename: str) -> str:
    """Loads and reads a summarized text from an artifact file."""
    # Load the artifact part from storage
    artifact_part = context.load_artifact(filename)
    
    if artifact_part and artifact_part.inline_data:
        # Decode the binary bytes back into a readable string
        return artifact_part.inline_data.data.decode('utf-8')
    return f"Error: Could not find artifact '{filename}'."

def list_summaries_tool(context: ToolContext) -> list[str]:
    """Lists all currently saved artifact filenames in the session."""
    # Retrieves an array of string filenames
    return context.list_artifacts()

# ==========================================
# 2. Define the Summarizer Agent
# ==========================================

summarizer_agent = LlmAgent(
    name="document_summarizer",
    model="gemini-2.5-flash",
    instruction="""
    You are a helpful assistant that summarizes text.
    When a user provides text, summarize it, and use the 'save_summary_tool' to store it.
    You can also list saved files or read them back to the user upon request.
    """,
    tools=[save_summary_tool, load_summary_tool, list_summaries_tool]
)

# ==========================================
# 3. Setup Services and Runner
# ==========================================

# Initialize the transient memory and artifact services
artifact_service = InMemoryArtifactService()
session_service = InMemorySessionService()

# Orchestrate the components
runner = Runner(
    agent=summarizer_agent,
    app_name="summarizer_app",
    session_service=session_service,
    artifact_service=artifact_service # Crucial: Attach artifact service to runner
)

# ==========================================
# 4. Execution Scenarios
# ==========================================

async def main():
    # Create the session context
    session = await session_service.create_session(
        app_name="summarizer_app", user_id="user_123"
    )
    
    # Scenario 1: User asks to summarize and save
    print("--- Saving an Artifact ---")
    prompt1 = types.Content(role="user", parts=[types.Part(text="Please summarize this and save it as 'ai_notes.txt': Artificial Intelligence is transforming the world by automating complex tasks, learning from vast amounts of data, and driving innovation across healthcare, finance, and transportation.")])
    
    async for event in runner.run_async(user_id="user_123", session_id=session.id, new_message=prompt1):
        if event.is_final_response():
            print("Agent Response:\n", event.content.parts[0].text)

    # Scenario 2: User asks to list and read the saved artifact
    print("\n--- Listing and Loading Artifacts ---")
    prompt2 = types.Content(role="user", parts=[types.Part(text="What files do you have saved? Please read the contents of 'ai_notes.txt' to me.")])
    
    async for event in runner.run_async(user_id="user_123", session_id=session.id, new_message=prompt2):
        if event.is_final_response():
            print("Agent Response:\n", event.content.parts[0].text)

    # Scenario 3: Explicitly Deleting an Artifact
    print("\n--- Deleting an Artifact ---")
    # Note: Deletion is executed directly on the Artifact Service instance for security,
    # rather than passing it as a tool to the LLM.
    await artifact_service.delete_artifact(
        app_name="summarizer_app", 
        user_id="user_123", 
        session_id=session.id, 
        filename="ai_notes.txt"
    )
    print("System: Deleted 'ai_notes.txt' successfully from storage.")

if __name__ == "__main__":
    asyncio.run(main())
```

>[!warning] Security Note on Deletion
>You will notice the delete_artifact method is not provided as a tool to the LlmAgent. Giving an LLM the ability to autonomously delete files is generally considered an unsafe design pattern in production. Instead, trigger deletions programmatically via standard application logic or lifecycle policies.


### Google ADK - Artifact Persistence and GCS

### Limitations of In-Memory Artifact Service

> [!warning] Volatility of InMemoryArtifactService
> The primary limitation of the **[[In-Memory Artifact Service]]** is that all binary data is stored temporarily in the application's RAM. 
> 
> * **Data Loss:** All artifacts are completely lost when the session ends, the agent restarts, or the server crashes.
> * **Scalability:** It cannot be shared across multiple server instances or worker nodes, making it unsuitable for distributed production environments or long-term file storage.

---
### Persistent Storage with Google Cloud Storage (GCS)

To overcome the limitations of in-memory storage, ADK provides the **[[GcsArtifactService]]**, which leverages Google Cloud Storage for durable, long-term persistence.

> [!info] Benefits of using GcsArtifactService
> * **Durability (Survives Restarts):** Artifacts stored in GCS persist across application restarts, crashes, and deployments.
> * **Scalability:** Leverages the massive scalability and high availability of Google Cloud infrastructure.
> * **Shared Access:** Allows artifacts to be shared across different application instances, microservices, or multiple agents by pointing them to the same GCS bucket.
> * **Native Versioning:** Explicitly stores each version of an artifact as a distinct GCS object (blob), ensuring historical file states are never accidentally overwritten.

---

### Implementation Code Snippets

### 1. Attaching a GCS Bucket via ADK Web CLI

> [!code] ADK Web Command
> When running your agent via the command line framework, you can map the artifact service directly to a GCS bucket using the `--artifact_service_uri` flag (or equivalent environment variables depending on your specific ADK version configuration).

```bash
# Run the agent using the ADK web interface and connect it to a GCS bucket
adk web main:root_agent --artifact_service_uri "gs://your-gcs-bucket-for-adk-artifacts"
```

### 2. Defining and Attaching GcsArtifactService in Python

>[!code] Python Implementation
Below is the programmatic way to define the GcsArtifactService and attach it to your Runner. Make sure your environment has the correct Google Cloud credentials (e.g., Application Default Credentials) to read and write to the bucket.

```python 
from google.adk.agents import LlmAgent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.adk.artifacts import GcsArtifactService

# 1. Define your agent
root_agent = LlmAgent(
    name="persistent_file_agent",
    model="gemini-2.5-flash",
    instruction="You process user files and save the outputs as artifacts."
)

# 2. Specify and initialize the GCS Artifact Service
gcs_bucket_name = "your-gcs-bucket-for-adk-artifacts"

try:
    gcs_service = GcsArtifactService(bucket_name=gcs_bucket_name)
    print(f"GcsArtifactService successfully initialized for bucket: {gcs_bucket_name}")
except Exception as e:
    print(f"Error initializing GcsArtifactService (check credentials): {e}")
    raise

# 3. Attach the GCS service to the Runner
runner = Runner(
    agent=root_agent,
    app_name="gcs_artifact_app",
    session_service=InMemorySessionService(), # Keep session local, but files in GCS
    artifact_service=gcs_service              # Inject the GCS persistence layer here
)
```
